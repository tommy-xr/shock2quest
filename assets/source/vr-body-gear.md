# VR body gear

The runtime belt and holsters are `../belt.glb` and `../holster.glb`, prepared
from the user-supplied Meshy exports:

- `Meshy_AI_cyberpunk_battle_belt_0927203435_image-to-3d-texture (1).glb`
- `Meshy_AI_tactical_holster_3d_0927204842_image-to-3d-texture.glb`

Rebuild them with Python, Pillow and NumPy:

```sh
python3 tools/prepare_vr_body_gear.py \
  --belt '/path/to/Meshy_AI_cyberpunk_battle_belt_0927203435_image-to-3d-texture (1).glb' \
  --holster '/path/to/Meshy_AI_tactical_holster_3d_0927204842_image-to-3d-texture.glb'
```

Each GLB embeds its color, normal and metallic/roughness maps, resized from
4096×4096 to 1024×1024. The belt's baked green light pixels are mapped to black
before resizing and its emissive factor is zero. The holster base color is
darkened to 61% brightness to match the belt's average texture luminance while
retaining its worn detail. PBR maps are retained for editing; gameplay currently uses
only base color.

Geometry retains the source topology (belt: 2,962 triangles; holster: 2,946).
Placement is baked into the vertices for consistent gameplay/editor loading:
both face -Z, the belt is 42 cm wide with its front at -30 cm, and the holster
is 24 cm tall with its center 1.7 cm above the attachment origin. This preserves
the existing metre-scale body mounts, personal card pose and interaction targets.
The shell is rendered at 80% size (19.2 cm tall) in both gameplay and the
editor. BIN item placement and size are authored separately in `../vr-holsters.json`;
GLB is used only for the wearable artwork.
Headset fit remains adjustable through the existing developer controls.

## Original procedural gear

The original belt, ammo pouch and rigid holster meshes were authored by
`tools/make_vr_body_gear.py`. The editable source is
`astra-vr-body-gear.blend`. Its procedural exports have been replaced by the Meshy assets. The ammo pouch
is part of the new belt mesh, with its own authored texture; the old separate
pouch and its glowing icon/rim are no longer rendered.

The shared `../astra-vr-body-gear-color.png` atlas was generated from scratch
with OpenAI image generation on 2026-09-08, without reference images or input
textures. It contains charcoal nylon, rubber, molded polymer and fabric
swatches. A subsequent image-generation edit of that original atlas reduced
the fabric weave to nearly smooth, low-contrast micrograin. No external
reference was used for the edit. A further edit darkened all swatches to
near-black charcoal for contrast with emissive indicators. It is not sampled from the glove atlas or System Shock 2 assets.
The geometry generator, GLB exports and Blender source use only this atlas.

Regenerate from the repository root:

```sh
/Applications/Blender.app/Contents/MacOS/blender --background --python tools/make_vr_body_gear.py
```

This legacy command also recreates unused `astra-vr-belt.glb` and
`astra-vr-holster.glb`; it does not overwrite the new Meshy exports.
The texture is a checked-in source asset, not regenerated by this command.
The GLBs embed geometry and reference the atlas by its adjacent filename.
The Blender source uses a relative image path. Studio previews are written to
`/tmp/astra-body-gear/`. Indicator recesses are geometry only in these assets;
the old pouch indicator is removed; holsters retain their runtime state indicators.

## Ammo pouch interaction

The front pouch supplies the selected ammo type for the gun held in the other
hand. Reach with an empty hand and squeeze; a held squeeze never draws twice.
Drawing uses an actual inventory clip, splitting larger stacks at the authored
clip size. Release a held ammo clip in the pouch to return it to the backpack.
Matching stacks can merge even when the backpack has no free cells. A refused
return retains the clip until a deliberate re-grip; empty selected stock gives
an audible refusal. Two occupied hands cannot draw until one is freed.

`vr_ammo_pouch_zones` displays the debug reach sphere. The player snapshot's
`hand_feedback.ammo_pouch` reports the same center, offers and refusal state used
by the interaction. Reach offsets still need seated and standing headset review.

The Blender material roughness is authored for editing; the current game GLB
material path uses base color only. The in-game material appearance is therefore
an initial approximation, not full glTF PBR rendering.

## Runtime feedback

The pouch has no visual readout or emissive overlay. Existing grab, refusal and
sound feedback remains active. Its grab target sits 2.5 cm behind the front of
the belt, inside the new pouch. Debug diagnostics still report selected ammo
and reserve availability; this is interaction state, not a rendered badge.

Each occupied holster has four small unlit indicators along its upper outer
edge, showing its own gun's loaded fraction, rounded up to quarters. Low ammo
uses amber; other nonempty loads use green. Empty guns have no filled bars and
a short red marker. Weapons without ammo use neutral cyan. Existing reach and
refusal markers remain unchanged. These indicators are self-lit surfaces,
not light sources illuminating nearby geometry.

The debug player snapshot exposes pouch interaction state and holster readouts as
`hand_feedback.body_gear`; `vr-body-state-lights.e2e.test.ts` verifies selected
ammo diagnostics, reserve availability, holster independence and dual wield behavior.
Final wearer readability and reach comfort still require headset review.
